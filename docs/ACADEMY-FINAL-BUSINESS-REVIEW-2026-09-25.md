# Academy OS 최종 사업·상품 검토

검토일: 2026-09-25. Pet Care OS의 최신 v2 사업 문서·브랜드 설정과 Academy OS의 실제 구현을 비교했다. Pet의 소스·문서만 읽었으며 다른 앱의 환경 변수·키·DB에 접근하거나 변경하지 않았다. 이 문서는 사업 검토 담당의 결과다. 통합 작업에서 실제로 고친 항목과 최종 테스트 결과는 이번 세션 인계 기록에서 확인한다.

**판정: 단일 학원의 ‘설명과 안내를 운영하는 제품’으로 좁히는 방향은 타당하다. 현재 구현의 가장 큰 약점은 기능 수가 아니라 반복 사용의 연결 부족이다.** 고급 홈페이지로 시작하되, 상담할 때마다·수업할 때마다 같은 설명을 다시 만드는 수고를 줄여야 지속적인 구독 이유가 생긴다. 승인 자료를 많이 보관하는 것만으로 해자가 완성되지는 않는다.

## 3. 실제 구현에서 발견한 우선 문제

아래는 검토 시작 시점의 코드 기준이다. 통합 작업에서 권고를 적용할 경우 해당 항목의 검증 결과를 별도로 남겨야 한다.

### P1 — 다음에 다시 쓰기 어렵다

- 근거: `src/studio.js`의 `reset`, `render`와 `st-library-card`는 빈 초안 시작과 기존 문서 열기 중심이다. `server/studio.js`의 `studio.save`는 기존 ID로 저장하면 `status: draft`, `secret: null`로 전환한다.
- 영향: 다음 상담이나 다음 수업에서 비슷한 자료를 만들려면 다시 입력해야 한다. 기존 공유본을 다음 사람용으로 덮어쓰면 앞서 전달한 링크도 중단된다.
- 즉시 권고: **‘이 자료로 새 초안’**을 제공한다. 새로운 ID로 만들고 승인·공유 상태는 승계하지 않는다. 기존 공개본은 보존한다. 가정별 안내의 호칭·목표·추가 질문·상담 연결처럼 수신자에 종속된 값은 기본적으로 비운다. 재사용할 교육 설명에도 개인 내용이 섞일 수 있으므로 공개 전 검토가 필요하다.
- 확인 기준: 복사본 저장 후 원본 링크가 유지되고, 복사본은 미승인으로 남으며, 원래 가정의 연결이나 비밀 링크가 따라가지 않는다.

### P1 — 자료가 쌓여도 찾기 어렵다

- 근거: `src/studio.js` 자료함은 종류 탭에 해당하는 항목을 모두 카드로 나열한다. 서버는 자료 최대 1,000개를 허용한다.
- 영향: 기록 수가 늘수록 원장의 검색 시간이 늘어난다. 축적 자체가 편익으로 바뀌지 않는다.
- 즉시 권고: 제목·반 이름 검색, 승인·재확인·초안 구분, 최근 수정 순서를 제공한다. 학원 내부에서 찾고 재사용하는 기능을 먼저 만든다.
- 확인 기준: 수십 개 자료에서 제목·반으로 원하는 자료를 찾고, 검색 중 자료를 열고 돌아와도 사용자 맥락을 유지한다.

### P1 — 상담과 제작 화면이 떨어져 있다

- 근거: `src/views.js`의 `website()` 상담 카드에는 요청 서류·학생 등록·취소가 있고, `src/studio.js`의 안내서에서는 반과 기존 상담을 다시 선택한다.
- 영향: 원장은 상담 목록과 스튜디오 사이에서 대상과 반을 다시 찾아야 한다. ‘상담에서 바로 이어지는 제품’의 체감이 약하다.
- 즉시 권고: 상담 카드의 **‘상담 안내서 준비’**가 올바른 반·상담을 선택한 미승인 초안으로 연결되게 한다. 예약 확정을 상담 완료로 해석하거나, 상담 목표·수업 적합 이유를 자동 지어내지 않는다.
- 확인 기준: 다른 반의 상담을 연결할 수 없고, URL만 바꿔 권한 없는 데이터에 접근할 수 없다. 저장하지 않은 입력을 보호한다.

### P1 — 체험에서 누른 수업과 상담 신청이 끊어진다

- 근거: `server/studio.js`의 체험 상담 이동은 기존 상담 페이지로 연결하며, 검토 시작 시점에는 수업 선택 맥락이 목적지에 전달되지 않았다.
- 영향: ‘이 수업 상담하기’라고 눌렀는데 다시 반을 선택해야 한다. 체험과 상담이 연결된다는 설명이 약해진다.
- 즉시 권고: 선택한 반을 상담 폼에 전달하되 최종 신청 전 변경·확인을 허용한다. 체험 세션을 학생 신원이나 실등록과 동일하게 취급하지 않는다.
- 확인 기준: 유효한 반만 미리 선택되며, 없어진 반·변경된 정보는 안전하게 다시 선택하게 한다.

### P1 — ‘한 번 기록’이라는 상품 약속보다 실제 입력이 많다

- 근거: `server/studio.js`의 쓰기는 원장 전용이며, `lesson` 자료의 `activity/why/next`는 직접 작성한다. 기존 강사 수업 `records`에서 수업 카드가 만들어지는 연결은 없다.
- 영향: 원장이 매번 수업 설명을 다시 쓰면 자동화가 원장 업무를 늘릴 수 있다. 교사가 기록하고 원장이 검토한다는 기존 운영 흐름과도 분리된다.
- 이번 범위 권고: 현재 기능을 ‘원장이 확인한 수업 설명의 제작·보관·재사용’으로 정확하게 설명한다. 먼저 원장 한 사람이 사용할 반복 업무를 검증한다.
- 후속 구현 조건: 실제 강사 계정·담당 반 범위·수업일·공유 가능한 수업 기록을 연결하고, 강사 초안→원장 승인 권한을 별도로 설계한다. 단순히 owner 검사를 제거하는 변경은 하지 않는다.

### P2 — ‘오늘의 수업’에 실제 수업일이 없다

- 근거: `shared/studio.js`의 기본 수업 카드 제목은 ‘오늘의 수업 이야기’이고, 저장 자료에는 작성·승인 시각이 있으나 수업일 필드가 없다.
- 영향: 며칠 뒤 자료를 다시 보거나 재사용하면 어떤 수업인지 모호하다. 승인 시각을 실제 수업일로 해석할 수 없다.
- 권고: 실제 수업일을 사람이 선택하게 하거나 제목에 날짜를 포함하도록 돕는다. 이전 자료를 새 초안으로 쓸 때 과거 날짜를 오늘 기록으로 바꾸지 않는다.

### P2 — 소개·운영 정보의 일관성은 아직 일부 범위다

- 강점: `sourceFor`·`studioCurrent`는 반·수강료·현재 시간표·학원 기준 변경을 확인해 오래된 승인본을 중단한다.
- 한계: 자유 입력 문장 안에 적은 다른 가격·일정의 모순을 전부 해석하는 기능은 아니다. 외부 블로그·플레이스까지 자동으로 고치는 기능도 아니다.
- 권고: 제품 설명은 ‘연결된 원본 변경 시 재확인’으로 제한한다. 이후 어떤 항목이 달라졌는지 보여 주면 원장의 재검토 부담을 줄일 수 있다.

### P2 — 분야별 예시 수와 분야별 완성도는 다르다

- 근거: `shared/studio.js`는 수학·영어·독서·미술·음악·코딩 선택형 예시를 제공한다. 미술 이미지 감상, 음악 연주, 체육 동작 피드백 기능은 아니다.
- 영향: 모든 교육 분야를 완성된 맞춤 에이전트로 판매하면 실제 상담에서 기대 차이가 커진다.
- 권고: 공개 데모는 한 과목에서 실제 원장 자료로 만든 체험을 보여 준다. 다른 분야는 ‘사용 가능한 예시’로 구분하고, 분야마다 필요한 자료와 검토 기준이 확보될 때 확장한다.

## 4. 상품을 한 문장으로 정리

**“우리 학원다운 수업을 보여 주고, 상담과 수업에서 확인한 설명을 다음에도 쉽게 쓰게 합니다.”**

무료 진입 상품은 기존 합의를 유지한다.

- 프리미엄 학원 웹사이트.
- 예약·문의 직원 한 명.
- 콘텐츠 직원 한 명.

유료 가설은 새 이름을 붙인 무료 업무가 아니라 **학원별 기준과 승인 자료를 반복 업무에 적용하는 편의**다. 예를 들어 상담별 안내 준비, 과목별 설명 자료 재사용, 변경된 안내 검토, 실제 강사와의 작성·승인 연결이 해당한다. 단, 현재 사용 가능한 무료 기능을 예고 없이 잠그거나 이 검토에서 새 결제·과금을 적용하지 않는다.

Pet의 0/29,000/49,000/79,000원은 해당 프로젝트에서도 예시 설정이다. Academy의 지원 원가·모델 사용량·지불 의사를 검증하지 않은 상태에서 같은 표를 복제할 이유가 없다. 초기에는 여러 유료 등급과 직원별 단가를 늘리기보다 **반복 업무 하나의 선택형 상품**을 먼저 검증한다.

무료 홈페이지는 맞춤 용역의 무제한 제공을 뜻하지 않는다. 템플릿·자료 입력·정해진 승인 흐름으로 제공 범위를 표준화하고, 사람이 대신 자료를 정리하거나 사이트를 운영하는 업무는 자동화와 구별해야 한다. 지원 인건비를 빼고 모델 비용만 계산하면 수익성을 과대평가하게 된다.

| 축적 대상                    | 고객에게 돌아오는 편익                      | 사업자가 확인할 지표                                |
| ---------------------------- | ------------------------------------------- | --------------------------------------------------- |
| 학원별 승인 설명·표현·예외   | 다음 자료를 빈칸부터 쓰지 않는다            | 새 초안의 재사용 비율, 작성·검토에 든 실제 시간     |
| 과목별 입력 양식과 검토 사례 | 필요한 입력이 명확하고 초안 오류가 줄어든다 | 다음 학원 설정 시간, 반복 지원 요청, 사실 수정 비율 |
| 자료와 원본 정보의 연결      | 바뀐 정보를 다시 찾기 쉽다                  | 오래된 안내를 찾아 수정하는 시간, 잘못된 안내 건수  |
| 배포·권한·공유·복구의 신뢰성 | 원장이 안심하고 지속해서 사용한다           | 공유 오류, 권한 사고, 복구 검증, 중단 후 회복 시간  |

이 효과는 자동으로 생기지 않는다. 승인 자료를 실제로 검색·재사용하고, 수정 사유를 구분하며, 같은 업무에서 더 적은 확인으로 정확한 결과를 내야 한다. 모아 둔 데이터 전체를 무조건 AI에 넣거나 모델 자체가 자동 학습한다고 설명하지 않는다.

고객에게 데이터 내보내기를 제공하면서도 편리함 때문에 남게 만드는 방향을 택한다. 오래된 사진·학생 정보를 내보내지 못하게 만드는 것을 사업 해자로 삼지 않는다. 학원 간에 학생 정보를 공유해야만 성립하는 구조도 초기 조건에 포함하지 않는다.

## 6. 작게 검증할 운영 모델

아래는 제안하는 파일럿 계획이며 현재 계약·실적이 아니다.

1. 첫 3~5개 학원에서 상담 안내 또는 수업 설명 중 실제로 자주 하는 업무 하나를 고른다. 다른 ERP의 전체 데이터 이관은 요구하지 않는다.
2. 도입 전 같은 업무의 준비·검토 시간을 기록한다. 샘플 한 건이 아니라 실제 반복 업무를 관찰한다.
3. 원장이 만든 자료와 승인 기준을 이용해 한 번 설정하고, 4주 동안 새 초안·승인·재사용을 반복한다.
4. 자료 작성 시간뿐 아니라 오류 수정·검토·고객지원 시간을 포함해 비교한다. 링크 열람·체험 클릭을 등록 성과로 바꾸어 말하지 않는다.
5. 같은 업무를 다음 주에도 스스로 쓰는지, 어느 기능 때문에 돈을 낼 의사가 있는지 확인한 뒤 유료 범위와 가격을 결정한다.

핵심 원가 식은 **학원 구독 수익 − 모델·메시징·호스팅 변동비 − 해당 학원 지원시간 비용 − 무료 고객을 유지하는 배분 원가**다. 숫자를 넣기 전 수익이 검증됐다고 주장하지 않는다. 방문자용 체험은 승인한 내용을 재사용하여 방문할 때마다 모델을 호출하지 않는 현재 방식이 원가 통제에 유리하다.

## 7. 최종 판정과 보류 항목

현재 구현의 장점은 승인본·변경 감지·공유 중지·교사용 메모 분리처럼 신뢰에 직접 영향을 주는 부분이다. 다음 개선의 중심은 **기존 상담에서 시작하기, 승인 자료를 찾아 새 초안으로 쓰기, 실제로 준비 시간이 줄었는지 확인하기**다. 이를 먼저 완성하면 Pet의 반복 사용 구조를 단일 학원에 맞게 적용할 수 있다.

이번 검토만으로 완료되었다고 말할 수 없는 범위는 실제 운영용 회원·보호자 연결, 다학원 서비스 격리, 외부 메시지·결제, 실제 AI 응답 품질, 학생별 장기 기록 재사용, 강사 수업 기록의 스튜디오 연결, 상업적 지불 의사다. 로컬에서 정상 작동하는 개선과 상용 서비스 준비 완료를 구분한다.

다기관 네트워크·공동 수업 개설·무제한 맞춤 개발·학생 자동 수준 판정·자동 성과 보장은 초기 상품에 추가하지 않는다. 사용자에게 이미 약속한 무료 웹사이트와 직원 두 명을 유지하고, 한 학원이 매주 다시 사용할 이유를 먼저 만든다.
