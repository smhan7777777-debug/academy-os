# 단일 학원에서 시작하는 고급 웹사이트와 맞춤형 에이전트

2026-09-25. 사용자의 후속 지시를 반영한 새 우선안. 이전 ‘배움연합·공동 개설’은 초기 진입안에서 제외한다. 아래 내용은 제품·사업 제안이며 아직 구현하거나 가격을 변경하지 않았다.

## 1. 이번에는 무엇을 파는가

**학원의 교육방식을 홈페이지에서 체험하게 하고, 상담부터 재원생 안내까지 그 학원의 방식으로 일하는 AI 직원을 제공한다.**

다른 학원·강사·지역 운영자를 모집할 필요 없이 원장 한 명이 결정할 수 있어야 한다. 학원이 이미 가지고 있는 소개문, 수업계획, 직접 만든 자료, 상담 메모, 승인한 피드백을 출발점으로 삼는다. 기존 ERP를 바꾸거나 모든 학생 데이터를 옮기는 것을 가입 조건으로 만들지 않는다.

무료 프리미엄 웹사이트와 예약·문의 직원, 콘텐츠 직원 두 명은 기존 제품의 기본 구성으로 유지한다. 추가로 파는 가치는 학원 고유의 수업 체험 제작, 상담별 안내 구성, 교수법과 설명 방식에 맞춘 업무 자동화다. 무료 직원에게 있던 업무를 이름만 바꿔 유료화하지 않는다.

초기 목표는 세 가지다. **방문자가 학원의 차이를 이해한다. 원장이 같은 설명을 반복하는 시간을 줄인다. 학부모가 실제 수업 내용을 이해한다.** 등록률·재등록률 향상은 검증할 결과이지 처음부터 보장할 효과가 아니다.

## 3. 아이디어 9개

### ① ‘우리 학원 수업 3분 체험’ 제작 직원

**홈페이지에서 그 학원의 설명·질문 방식을 경험한다.** 수학이면 원장이 직접 만든 문제 하나를 풀고, 선택한 답에 맞는 힌트를 본 뒤 다시 시도한다. 독서면 짧은 글의 관점을 선택하고 선생님의 다음 질문을 만난다. 미술이면 명암·구도 선택에 따른 예시를 살펴본다.

- 입력: 사용 권한이 있는 예제 1개, 교사의 풀이·설명, 지도할 때 주로 쓰는 질문.
- 에이전트 업무: 예제를 짧은 체험 순서로 구성하고 답별 설명·힌트·마무리 안내를 초안으로 만든다. 검토용 정답·근거도 함께 제시한다.
- 웹사이트 결과: ‘우리 수업을 경험해 보세요’ → 시도 → 힌트 → 재시도 → 실제 수업 방식·상담 안내.
- 작은 첫 버전: 객관식/선택식 한 개, 교사가 검토한 분기형 설명, 연락처 입력 없이 이용. 실시간 자유대화와 자동 수준 판정은 넣지 않는다.
- 난도: **낮음~중간**. 예시 문항과 사이트 기반은 있지만 체험 작성·검토·분기형 표시를 추가해야 한다.
- 검증: 시작·완료·상담 요청의 연결, 교사의 검토 시간. 짧은 체험으로 아이의 수준·성향을 판정하지 않는다.

AI는 공개 전에 제작을 담당하고 승인된 결과는 재사용할 수 있다. 방문자마다 모델을 호출하지 않아도 되므로 비용과 오류를 통제하기 쉽다. 공개용으로 허락받지 않은 교재를 체험 자료로 재게시하지 않는다.

### ② ‘상담 후 우리 아이 수업 안내서’ 직원

**상담이 끝나면 그 가정이 다시 읽어볼 수 있는 깔끔한 안내 페이지를 만든다.** 원장이 상담한 내용을 세 줄로 적으면 합의한 목표, 상담에서 검토한 반, 첫 수업 준비, 일정과 확인 사항을 학원 자료에 맞춰 구성한다.

- 입력: 보호자가 직접 말한 목표·가능 시간, 원장의 상담 메모, 확인된 반·가격·일정.
- 에이전트 업무: 적합하다고 설명한 이유와 아직 확인할 점을 구분하고, 공개 가능한 수업 사례를 연결한다.
- 웹사이트 결과: ‘이번 상담에서 함께 확인한 내용’ → ‘검토한 수업’ → ‘수업 예시’ → ‘첫 방문 안내’ → ‘질문 남기기’.
- 작은 첫 버전: 원장이 선택한 반 1~2개를 설명하고 승인 후 링크를 직접 전달한다. 자동 연락이나 심리 추정은 필요 없다.
- 난도: **중간**. 상담 기반은 있으나 개인 페이지 권한·만료·철회가 필요하다. 처음에는 개인 식별정보 없는 출력용 안내서로 검증할 수 있다.
- 검증: 상담 뒤 반복 질문 수, 원장의 작성·수정 시간, 실제 등록 확인. 페이지 열람을 등록이나 관심도의 확정적 증거로 세지 않는다.

비용·시간표는 확인 시각을 표시하고, 변경되면 재확인이 필요하다. 열람 링크를 안다는 것만으로 모든 자녀 정보에 접근하게 하지 않는다.

### ③ ‘수업 한 번, 설명 자료 세 가지’ 직원

**선생님이 수업을 한 번 기록하면 대상에 맞는 설명을 준비한다.**

| 결과 | 무엇을 담는가 | 근거 |
|---|---|---|
| 학부모용 수업 카드 | 무엇을 했고 왜 했는지, 교사가 실제 확인한 것, 다음 활동 | 해당 수업과 해당 학생에게 공유 가능한 기록 |
| 다음 수업 준비 메모 | 미완료 활동, 필요한 자료, 교사가 확인할 질문 | 교사용 기록 |
| 공개용 수업 소개 초안 | 수업 목표·지도 방식·교사가 만든 예시 | 공개 가능하게 별도 선택한 자료 |

- 입력: 수업 주제·활동 체크, 선택 메모. 초기에는 음성 인식·사진 자동 해석 없이 텍스트로 시작한다.
- 작은 첫 버전: 반 전체 수업 카드와 공개 소개를 준비하되, 개인 관찰을 입력하지 않은 학생의 맞춤 평가를 만들지 않는다.
- 난도: **낮음~중간**. 현재 수업 기록·리포트·콘텐츠 승인 구조를 확장한다.
- 검증: 선생님의 전체 입력·검토 시간이 줄었는지, 학부모가 수업을 이해하는지.

학생 기록을 이름만 지워 곧바로 광고로 바꾸지 않는다. 공개용은 교사 예제와 수업 방법 중심으로 별도 승인한다. 미술 작품·학생 사진 등은 공개 권한을 따로 확인한다.

### ④ ‘첫 네 번의 수업’ 적응 안내 직원

**새로 등록한 가정의 첫 수업 준비와 적응 안내를 학원 방식에 맞춰 준비한다.** 첫 방문 위치·준비물, 두 번째 수업에서 할 일, 교사가 확인한 질문, 다음 상담 주제를 한 흐름으로 보여준다.

- 입력: 학원의 신규 등록 안내, 계획된 첫 수업 순서, 교사가 직접 확인한 메모.
- 작은 첫 버전: 확인된 수업 일정에 맞는 안내 초안을 원장 화면에 준비하고 승인 후 학부모 화면에 반영.
- 난도: **중간**. 교사·학부모 계정과 전달 상태가 실제로 동작해야 한다.
- 검증: 준비물·첫 방문 관련 반복 문의, 안내 작성 시간, 부모의 이해도. 재등록 효과는 더 긴 관찰이 필요하다.

‘4회’는 예시다. 음악·체육·보습 등 실제 수업 운영에 맞춰 바꾼다. 아이의 불안·적응 수준을 자동 추정하지 않는다.

### ⑤ ‘다음 수업 복귀 준비’ 직원

**결석한 학생에게 다음 수업에 필요한 최소 준비를 정리한다.** 교사가 승인한 범위에서 지난 수업 핵심, 봐야 할 예제, 다음 시간 확인할 질문을 작은 카드로 제공한다.

- 입력: 실제 결석, 해당 수업의 수업안·사용 허락된 자료, 교사가 정한 필수 준비.
- 작은 첫 버전: 학습지·설명 카드 한 장을 준비하고 강사가 확인한다. 무제한 문제 생성이나 새 동영상 강의 제작은 하지 않는다.
- 난도: **중간**. 결석 기록은 있으나 수업안과 자료 연결·새 승인 흐름이 필요하다.
- 검증: 강사의 보충 설명 시간, 준비 자료 이용 여부, 다음 수업 진행의 편의.

출결이 없으면 결석으로 추정하지 않는다. 카드를 봤다는 사실을 학습 완료로 표시하지 않는다. 교사의 보강을 대체한다고 약속하지 않는다.

### ⑥ ‘작품과 과정이 보이는 개인 전시실’ 직원

**미술·음악·글쓰기·코딩 학원의 특성을 고급 웹사이트에서 보여준다.** 결과물을 시간순으로 놓고, 학생의 설명과 교사의 실제 피드백을 아름답게 구성한다.

- 입력: 선택한 작품·글·코드 이미지, 날짜, 교사의 주석. 초기에는 사진·문서 위주이며 연주 영상의 자동 평가를 하지 않는다.
- 작은 첫 버전: 학생별 비공개 작품 3개와 교사 코멘트. 공개 갤러리는 별도 허락받은 자료만 사용한다.
- 난도: **중간**. 업로드·보관·접근 통제가 필요하다.
- 검증: 제작 시간, 부모의 유용성 평가, 교사 상담에서 재사용 여부.

다른 학생의 점수와 비교하거나 AI가 작품만 보고 재능·성격을 단정하지 않는다. 재등록 상담에서는 등록을 압박하는 도구보다 실제 과정을 설명하는 자료로 사용한다.

### ⑦ ‘원장님의 지도 방식’ 강사 보조 직원

**원장이 원하는 설명·피드백 방식을 신규 강사도 활용하게 한다.** 원장이 승인한 좋은 피드백 예시와 수정 사례를 바탕으로 수업안·첨삭 문구의 초안을 점검한다.

- 입력: 교수 원칙 몇 가지, 좋은 예시·수정 예시, 과정별 수업 기준.
- 예: ‘바로 정답을 알려주기 전에 학생에게 풀이의 어느 단계인지 질문한다’, ‘영어 첨삭은 이번 수업의 목표 표현부터 다룬다’.
- 작은 첫 버전: 강사가 작성한 문장을 원장 기준과 대조하고 수정 제안·근거를 표시한다. 학생 평가나 강사 인사평가를 자동 결정하지 않는다.
- 난도: **중간**. 모델 연결, 자료 검색, 역할별 권한과 품질 평가가 필요하다.
- 검증: 원장의 검수 시간과 반복 수정 비율. 원장의 과거 문장에 무조건 가까워지는 것을 교육 품질 향상으로 보지 않는다.

학원별 차이가 가장 많이 쌓일 수 있는 후보지만, 초기에는 원장 한 사람의 명확한 예시가 있는 업무 하나로 좁힌다.

### ⑧ ‘학원 안내의 틀린 곳 찾기’ 직원

**시간표·가격·반 이름을 바꾸면 영향을 받는 안내를 찾아 수정안을 준비한다.** 홈페이지, FAQ, 상담 안내서, 다음 수업 준비 카드가 서로 다른 정보를 말하는 상황을 줄인다.

- 입력: 학원이 확정한 운영 정보와 변경 이력.
- 작은 첫 버전: 우리 시스템 안에 저장한 자료만 점검. 외부 블로그·플레이스는 수정할 문구와 링크를 제시하고 사람이 반영한다.
- 난도: **낮음~중간**. 기존 버전·승인 기반을 자료 의존관계까지 확장한다.
- 검증: 잘못된 안내·재작업 수, 수정 제안의 정확성. 가격·시간·수신자 변경은 다시 확인한다.

외부 채널 수정까지 자동 완료했다고 표시하지 않는다. 화면은 화려하지 않아도 신뢰와 지원 원가에 직접 영향을 주는 기능이다.

### ⑨ ‘작은 학부모 설명회’ 제작 직원

**반복하는 학원 설명을 짧은 웹 설명회로 만든다.** 원장의 소개문·기존 슬라이드에서 교육 철학, 수업 사례, 한 학기의 흐름, 자주 묻는 질문을 고급 페이지로 구성한다.

- 방문자는 ‘처음 시작’, ‘기존 경험 있음’, ‘방학 과정 관심’ 등 본인이 고른 관심사에 따라 관련 부분을 먼저 본다.
- 작은 첫 버전: 페이지와 승인된 질문·답변. 아바타 영상·원장 음성 복제·실시간 방송은 필요 없다.
- 난도: **낮음~중간**. 현재 사이트 제작·지식 슬롯·콘텐츠 승인을 활용한다.
- 검증: 설명회 자료 작성 시간, 상담에서 기본 설명에 쓰는 시간, 실제 상담 요청.

기존 무료 콘텐츠 직원의 글 작성을 유지하면서, 과정별 구성·방문자 선택 동선·수업 체험 결합을 추가 상품의 가치로 검증한다.

## 4. 다양한 교육 분야를 지원하는 방법

업종을 함께 영업하거나 수업을 연결할 필요는 없다. **같은 엔진에서 입력 양식과 산출물의 형식을 다르게 제공**한다.

| 학원 종류 | 처음 보여줄 체험 | 유료 맞춤 업무 후보 |
|---|---|---|
| 수학·과학 | 예제→힌트→재시도, 현상 선택→설명 | 교사 기준의 풀이 피드백·결석 복귀 카드 |
| 영어·독서·논술 | 문장·짧은 글→질문→교사의 설명 | 첨삭 기준 점검·상담 안내서 |
| 미술·디자인 | 구도·색·명암 선택과 교사 예시 | 작품 전시실·수업 설명 카드 |
| 음악 | 교사가 만든 악보·연습 예시와 짧은 설명 | 연습 안내·교사 주석이 있는 과정 기록 |
| 코딩·로봇 | 교사가 검토한 실행 결과 선택·디버깅 예시 | 프로젝트 설명·강사용 지도 가이드 |
| 체육·무용 | 실제 수업 단계·준비 안내의 선택형 투어 | 첫 수업 적응 안내·지도자가 확인한 활동 카드 |

동작·연주·발음의 정밀 자동 평가는 별도 품질·미디어 처리 과제다. 분야를 추가할 때 명칭만 바꾸면 완성된다고 계산하지 않는다. 공통 디자인·권한·승인을 공유하고 교육 내용의 차이는 검토된 팩으로 관리한다.

## 5. 학원별 맞춤화 자체를 반복 가능한 상품으로

맞춤화는 매번 새 코드를 개발하는 용역이 되지 않아야 한다. 초기에는 다음 절차를 공통으로 제공한다.

1. 학원 소개·반 안내·직접 만든 예제·좋은 피드백 사례를 소량 받는다. 없는 자료는 입력칸으로 묻는다.
2. AI가 확인한 사실, 설명 방식, 금지할 표현, 공개 가능 범위를 나눠 초안을 만든다. 없는 내용을 채워 넣지 않는다.
3. 원장이 사실과 교육 기준을 확인한다.
4. 같은 자료로 체험 페이지·상담 안내·수업 카드의 시안을 보여준다.
5. 실제로 쓰는 업무를 선택하고, 대표 상황에서 결과를 검토한 뒤 켠다.
6. 수정 이유를 ‘사실 수정 / 표현 선호 / 교육 기준 / 일회성 예외’로 구분해 남긴다. 반복 지침으로 승격하는 것은 원장이 확인한다.

원장 말투를 흉내 내는 것보다 **어떤 자료를 근거로, 누구에게, 어떤 형식으로, 어느 단계까지 처리하는지**를 맞추는 것이 중요하다. 초기에는 학원별 자료 검색·설정·승인 예시 재사용으로 구현하고 모델 자체 재학습을 필요조건으로 삼지 않는다.

공개 체험·설명회는 미리 생성해 검토한 결과를 재사용한다. 상담별·학생별 자료는 필요한 시점에 생성한다. 이 두 방식을 나누면 방문 트래픽이 증가할 때 모델 비용이 비례해 늘어나는 것을 줄일 수 있다.

## 6. 작은 회사가 쌓을 수 있는 방어력

| 자산 | 쌓이는 것 | 경쟁우위가 성립하는 조건 |
|---|---|---|
| 학원별 설정과 검토 사례 | 실제 교수 원칙, 승인 자료, 반복 예외 | 같은 업무의 수정률과 원장 검토시간이 줄어야 함 |
| 분야별 완성된 업무 팩 | 필요한 입력·출력·검토 기준·실패 사례 | 다음 학원 설치시간과 지원시간이 줄어야 함 |
| 웹사이트와 업무의 연결 | 같은 승인 자료로 체험·상담·수업 설명을 제공 | 원장이 도구 사이에 다시 입력하는 일이 줄어야 함 |
| 고급 디자인과 운영 품질 | 자료가 늘어도 일관된 화면·정확한 정보 | 실제 가정이 이해하고 원장이 계속 사용해야 함 |

어느 한 기능도 독점적이라고 주장할 수 없다. 초기 방어력은 **학원마다 정확하게 맞춰 설치하고, 좋은 결과를 반복해서 내는 제품 완성도와 설치·지원 효율**에 있다. 고객의 자료는 내보낼 수 있어야 한다. 각 학원의 비공개 수업자료를 다른 학원에 재사용할 권리가 생기는 것은 아니다. 회사 공통 팩에는 이용 권한이 확보된 예시와 일반화한 업무 구조만 사용한다.

‘사용할수록 원장에게 맞아진다’도 자동으로 성립하지 않는다. 입력이 적거나 수정 이유가 모호하면 좋아지지 않을 수 있다. 같은 대표 과제에서 수정 횟수·오류·검토시간을 반복 측정해야 한다.

## 7. 우선순위와 수익 구조

**첫 공개 시연은 ① 수업 3분 체험과 ⑨ 작은 설명회. 첫 유료 검증은 ② 상담 안내서 또는 ③ 수업 설명 카드 중 원장의 반복 업무가 더 큰 것 하나.**

이렇게 하면 공개 예제만으로 첫 가치를 보여줄 수 있다. 개인정보를 사용하는 기능에는 실제 계정·보호자 권한·보관·전달 설계가 추가로 필요하다. 다기관 연합이 없어도 되는 것과 서버·모델·인증이 전혀 필요 없다는 것은 다르다.

- 무료: 기존 프리미엄 웹사이트, 예약·문의 직원, 콘텐츠 직원 유지.
- 선택적 초기 설정 서비스: 원장 자료를 정리하고 맞춤 체험·업무 팩을 구성하는 실제 작업에 과금하는 안. 셀프 설정은 가능하게 하고 필수 숨은 제작비로 만들지 않는다.
- 월 구독: 선택한 맞춤 업무의 반복 실행·변경 관리·지원에 과금. 직원별 별도 과금보다 업무 묶음으로 설명할 수 있다.
- 추가 상품: 실제 요청이 있는 과정·분야별 검토 팩. 먼저 수요가 확인된 범위만 제작한다.

이번에는 새로운 확정 가격을 정하지 않는다. 기존 요금제를 바꾸지 않고, 작업 원가와 지불 의사를 확인한다. 신규 등록이 얼마나 늘었다는 보장형 수익모델도 두지 않는다.

측정할 원가: 초기 자료 정리·설정 시간 + 월 모델·알림·저장 비용 + 원장·교사 지원 시간 + 학원별 수정 요청. 입력 자료가 제각각이라 매달 제작 대행을 해야 한다면 구독 범위를 줄이거나 별도 서비스로 명확히 구분한다.

## 8. 현재 코드에서 가져올 것과 새로 필요한 것

| 현재 확인한 기반 | 새로 필요한 부분 |
|---|---|
| `shared/templates.js`, `server/website-pages.js`: 17종 디자인·사이트 렌더링 | 체험·설명회·안내서용 데이터 기반 블록 |
| `src/portal.js`, `server/domain.js`: 예시 문항·상담 연결 | 교사가 작성·검토하는 체험, 힌트·분기 설명. 현재 예시 퀴즈를 새 체험 기능 구현으로 간주하지 않음 |
| `server/domain.js`: 수업 기록·리포트·지식 답변·콘텐츠 승인 | 학원별 수업 기준, 공통 수업안, 여러 산출물의 서로 다른 공개 범위 |
| `server/store.js`: 버전·승인·감사 기반 | 승인 예시·수정 이유·자료 의존관계와 변경 점검 |
| `/start`: 텍스트 자료 기반 웹사이트 초안 | 실제 모델 연결·평가·사용량 관리. PDF·이미지·음성은 필요 확인 후 |

현재 외부 AI는 연결되지 않았고 회원·보호자 연결도 데모 기반이다. 학원 하나에서 쓰는 첫 제품에도 필요한 배포·인증·모델 연동은 실제로 구현해야 한다. 이번 제안은 그 작업을 없앤다는 주장이 아니라 외부 영업망·공동 운영의 선행 부담을 제거하는 설계다.

## 9. 작은 검증

첫 학원 한 곳의 실제 자료로 체험 하나와 안내서 하나를 만든 뒤, 원장과 교사가 기존 방식과 비교한다. 원장에게 자료를 새로 많이 작성하게 했다면 그 시간도 포함한다.

- 학원 고유의 설명 방식이 결과에 보이는가?
- 원장이 고치는 시간까지 포함해 반복 설명 업무가 줄었는가?
- 부모가 수업 내용을 이해하고 다음 행동을 알 수 있는가?
- 사실 오류·비공개 자료 노출 없이 승인과 수정이 가능한가?
- 다른 학원에 설정할 때 별도 코딩 없이 재사용할 수 있는가?

방문자 수가 적으면 전환율 차이를 성과처럼 단정하지 않는다. 초기에는 실제 문의·상담 사례와 처리시간을 우선 확인한다. 비교 기간·유입 경로·할인·사람의 추가 지원을 함께 기록한다.

권고 문구: **“원장님의 가르치는 방식을, 홈페이지와 AI 직원에 담아드립니다.”**

본 문서와 인계만 변경했다. 앱·DB·가격·타 프로젝트는 수정하지 않았고, 고객 연락이나 실제 결제·발송을 수행하지 않았다.
