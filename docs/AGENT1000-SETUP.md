# 배움결 AI 직원 연결 · 운영자 작업 안내

2026-09-25 구현 기준. 디자인은 기존 배움결 테마를 사용한다.

## 지금 구현된 범위

### 클릭 중심 화면 (최신)

- `/agents`는 업무 선택 홈이다. 역할별 색상을 구분하고 전체 입력 폼은 상세 작업실(`/agents?view=advanced`)로 옮겼다.
- 팝업: `/agents?agent=academy-popup`에서 안내 종류·수업·기간·색상·표시 방식을 선택 → 실제 선택한 홈페이지 위 미리보기 → 게시. 기본 서식은 글 입력과 AI 연결 없이 작동한다. 게시·예약·수정 교체·내리기·모집 출처와 수업이 연결된 상담 버튼을 지원한다. 문구를 직접 바꾸는 입력은 접혀 있다.
- 팝업의 원장 승인과 앱 반영은 한 번의 게시 버튼으로 처리하지만 승인본·게시 이력은 보관한다. 공개 사이트에는 유효한 안내 중 가장 최근 게시물이 먼저 표시된다. 일반 선택형 문구는 AI 생성물로 표시하지 않는다. AI 맞춤 문구가 필요하면 상세 작업실을 사용한다.
- 다른 핵심 직원: 학생/문의/채널 선택 → 자동으로 가져온 자료 확인 → AI 초안 만들기 → 결과 확인·바로 반영. 별도의 초안 저장 버튼과 결재함 이동을 생략했고 같은 승인 기록을 남긴다. 페이지를 다시 열어도 실행 ID로 이어가며 중복 호출하지 않는다.
- 수업일지·장부는 저장된 수업이 없으면 수업 기록으로 안내한다. 진로 관심 분야는 실제 학생이 말한 항목만 선택한다. 답안지 분석은 사진 자료가 필요하며, 사진 없는 수업 기록 리포트로 이동할 수 있다. 없는 관찰·성적·사진을 만들어 채우지 않는다.
- 실제 AI 제공자 인증은 여전히 필요하다. 클릭형 화면 구현과 실제 모델 호출 검증을 구분한다. 사진 분석·예외적인 상세 업무에는 추가 자료 입력이 남는다.
- 검증 명령: `npm run test:quick-agents` (격리 DB·모의 AI). 실제 홈페이지 팝업 게시/교체/내리기, 상담 수업 연결, 4개 화면 너비, 플레이스 입력 없이 생성/승인, 새로고침 후 중복 실행 방지를 검사한다.

- 원장실 상단의 대표 5직원과 `/agents`의 5개 업무팀으로 시작한다. 40종 입력 계약과 전용 n8n 호출 경로를 유지하고 추가 검토 8종은 구분한다. 홈페이지 문의·학생 목록에서 해당 자료를 연결해 시작할 수 있다.
- 기존 학생/반/확정 학원 지식으로 입력 준비. 학생 별칭 사용, 비공개 교사 메모 제외. 함께 전송할 학원 근거를 초안에서 확인.
- 입력 초안 저장 → 실제 실행 요청 또는 30일 이내 예약 → 결과 본문 수정 → 통합 결재함 → 원장 승인 → 연결된 앱 화면 반영. 기존 승인 텍스트 내려받기는 이전 작업에 유지된다.
- 문의 답변은 원래 문의에, 팝업/소식은 홈페이지에, 학생을 연결한 수업일지·브리핑·진로·재등록 안내는 해당 보호자 공간에 반영된다. 학습 장부·플레이스 등 나머지 결과는 원장 내부 문서로 보관된다. 게시 시작/종료와 상담 신청 링크를 지원하고 예약에 모집 소식 출처를 기록한다.
- 수업일지는 기존 수업 기록으로 준비할 수 있다. 브리핑 엔진은 별도로 답안지 사진이 필수다. 승인된 학생 학습 장부는 이후 직원 실행의 근거로 가져오며 비공개 교사 메모는 제외한다.
- 작업·원본 결과·수정 승인본·승인 해시·이력은 SQLite `agent_runs`에 저장. 페이지를 닫아도 서버 작업은 계속 처리된다. 서버가 꺼진 동안은 실행되지 않으며 다시 시작하면 대기 작업을 검사한다.
- 동일 요청 ID의 중복 초안 생성 차단, 작업 선점, 월 요청 한도, 자료 버전 변경 시 재확인, 취소, 실행 실패·보류·타임아웃 구분. 실행 결과가 불명확하면 자동 재전송하지 않는다.
- 원장 권한·기존 CSRF·호출 빈도 제한 적용. 다른 학원의 작업 열람 차단. 전용 namespace `prof` 고정, 서버에서 학원 ID 확정, 브라우저가 웹훅 경로·학원 매핑·비밀을 지정하지 못함.
- 기존 규칙 직원의 '지금 준비' 결과에 생성 문서 수 또는 대상 없음/기존 문서 존재 이유 표시.

**40종은 호출 어댑터와 입력 계약의 구현 수다. 실제 Agent1000 응답으로 40종 전부가 검증됐다는 뜻이 아니다.** 테스트에서는 실제 비용·발송이 발생하지 않는 모의 제공자를 사용했다.

## 사용자/플랫폼 운영자가 준비할 것

1. 학원 전용 `wf-prof-*` 40개 워크플로의 현재 활성화 여부와 Bearer 인증을 확인한다. 공유 운영본 `wf-*`를 수정하지 않는다. 로컬 랩 README는 사본의 운영 DB 쓰기를 껐다고 설명하지만, 운영자는 현재 워크플로에서도 저장·발송 부작용이 없는지 확인해야 한다. `persist:false`만으로 모든 워크플로 부작용이 차단된다고 가정하지 않는다.
2. 이 학원에 맞는 전용 `shop_id`를 확인한다. 다른 학원이나 타 OS의 ID/DB를 넣지 않는다. 현재 배움결 기본 학원 ID는 `forest`이며 향후 실제 테넌트로 전환하면 매핑을 함께 바꾼다.
3. 아래 환경변수를 실행 서버의 비밀 설정 또는 gitignored `.env`에 입력한다. 키를 채팅·문서·Git에 붙이지 않는다.
4. 실제 사용은 계속 실행되는 Node 서버와 영구 디스크에서 시작한다. 로컬 PC는 기능 검증용으로 사용할 수 있다. 공개 Vercel 체험 배포의 실제 AI 실행은 의도적으로 차단되어 있다.

```dotenv
ACADEMY_DEMO=0
ACADEMY_AGENT_ENABLE=1
ACADEMY_AGENT_BASE_URL=https://<전용-n8n-호스트>
ACADEMY_AGENT_BEARER=<서버-비밀-설정에만-입력>
ACADEMY_AGENT_SHOP_ID=<학원-전용-매핑>
ACADEMY_AGENT_ACADEMY_ID=forest
ACADEMY_AGENT_NAMESPACE=prof
ACADEMY_AGENT_MONTHLY_LIMIT=100
```

필요하면 `ACADEMY_DATA_DIR`에 이 앱만 쓰는 영구 저장 경로를 지정한다. 기본 Windows 저장 위치는 `%LOCALAPPDATA%/AcademyOS/data`다. 실제 운영에서 디스크 백업과 복원 검증을 구성한다. 원격 호스팅은 HTTPS·도메인·접근 경로를 별도 설정해야 하며 현재 서버는 localhost 바인딩이다.

```powershell
npm run agents:check
npm run build
npm start
```

`agents:check`는 설정 형식과 준비 여부만 출력하며 비밀을 출력하거나 모델을 호출하지 않는다. 불완전하면 종료코드 1이다. 환경변수를 바꾼 후 서버를 재시작한다.

원장 로그인은 서버 데이터 폴더의 `local-accounts.txt`에 저장된 해당 원장 계정을 사용한다. 이 파일을 공유하거나 공개 저장소에 추가하지 않는다. 공개 데모의 계정 전환 기능을 실제 유료 엔진에 연결하지 않는다.

## 첫 실제 검증 순서

1. 수업일지에 가상 학생 별칭과 가상 수업 기록을 입력하고 초안을 저장한다.
2. 전송 입력과 학원 근거를 확인한 뒤 AI 실행을 요청한다. 제공자의 실행 로그와 배움결 결과가 일치하는지 확인한다.
3. 결과를 수정하고 승인한다. 새로고침/서버 재시작 후 승인본이 유지되는지 확인한다.
4. 핵심 9종을 각각 확인한다: journal, ledger, reenroll, inquiry, study-ledger, briefing, place, career, popup.
5. 나머지 특화 4종과 공통 27종을 확인한다. 특히 이미지 권한, 목록 숫자 형식, 플레이스 추가 규격, 지역·영업시간 근거, 데이터 없는 질문의 응답을 검증한다.
6. 응답 봉투는 현재 `{ ok, status: "ok", data: {...}, warnings? }`를 요구한다. 엔진이 다른 규격을 쓰면 성공 판정을 느슨하게 바꾸지 말고 실제 응답을 기준으로 코드별 정규화기를 보완한다. 200 blocked/disabled는 성공으로 표시하지 않는다.

각 코드에서 정상·입력 부족·실패·부족한 근거·재요청·자료 변경·승인을 확인해야 한다. 개발 테스트 통과는 실제 모델 품질·운영 계정 권한·발송 연결 검증을 대체하지 않는다.

## 아직 자동화되지 않은 부분

- 8개 추가 정의는 카드와 준비 상태만 표시한다. CORE-31~35의 기존 비공개 LLM 엔진 연결, CORE-17/20의 학원용 수정은 별도다. CORE-TREND는 네일 전용이므로 학원 실행 대상이 아니다.
- 현재 AI 업무실은 원장 전용이다. 학생·학부모가 직접 AI를 실행하는 화면과 개인별 이용 한도는 추가 작업이다.
- 입력은 기존 계약에 맞춰 준비하지만 재고·포인트·외부 채널 통계 등의 원장이 없는 업무는 그 데이터를 자동으로 공급하지 않는다. 없는 데이터를 '0'으로 간주하지 않는다.
- 문자·알림톡 전송, 플레이스 등 외부 플랫폼 자동 게시, PG 결제/환불은 연결되지 않았다. 앱 내부 문의 답변·홈페이지 게시·보호자 공간 반영과 외부 발송을 구분한다.
- 새 작업은 연결한 문의/학생/학원 자료의 해시를 실행·결재·반영 단계에서 검사한다. 연결 정보가 없는 이전 작업은 전체 revision 검사로 유지한다.
- 반복 주기 스케줄러·분산 작업 서버·Supabase 전환·상용 회원 가입/권한 설정은 이번 구현 범위 밖이다. 현재는 동일 호스트의 SQLite 작업 대기열과 날짜 지정 1회 예약 실행이다.
- CORE-28은 학원 서비스 Q&A이며 교과 튜터 대체품이 아니다. 맞춤 학습 플랜·시험 대비 스케줄러·학습 스트레스 지원의 기존 최신 엔진 확보/추가 구현이 필요하다.

## 엔진 자산 유지

공개 앱에 포함된 것은 표시용 이름·입력 계약·고정 호출 경로뿐이다. 랩 전체, 모델 프롬프트, 실제 워크플로 내부, 인증값은 복사하지 않았다. 최종적으로 비공개 Agent1000 게이트웨이를 도입할 때 이 어댑터의 호출 계층만 교체하고 배움결 기록·화면·승인 작업은 유지한다.
