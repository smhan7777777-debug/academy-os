# 원장실 Academy OS v4

**무료 프리미엄 학원 웹사이트 + 그 웹사이트를 운영하는 원장실 OS**입니다. 무료 웹사이트 제공으로 학원을 만나고, 웹사이트의 상담·문의·등록 업무와 승인한 콘텐츠를 OS에서 연결하여 관리하는 것이 제품의 핵심입니다.

2026-09-25 최종 검토 버전: **[수업 스튜디오](http://localhost:5177/studio)** · [웹사이트 제작](http://localhost:5177/start) · [학원 홈페이지](http://localhost:5177/site). 현재 실행 포트는 5177이며, 아래 5173은 터미널 기본 포트 예시입니다. 검토 결과는 [최종 보고서](FINAL_REVIEW_2026-09-25.md)를 참고하세요.

외부 공유 자료: **[Academy OS 사업모델 소개서 · A4 4쪽 PDF](docs/reports/Academy-OS-Business-Brief-2026-09.pdf)**. 고객 가치, 이용 흐름, 수익 구조와 경쟁력, 도입 계획을 설명하며 현재 구현과 검증할 사업 가설을 구분합니다. 수정·재생성은 [소개서 안내](docs/reports/README.md)를 참고하세요.

**수업 스튜디오(`/studio`)**에서 한 학원의 수업 체험·상담 안내서·수업 설명 카드를 작성하고 검토·승인합니다. `/learn`의 공개 체험은 질문 → 힌트 → 재시도 → 설명 → 기존 상담 신청으로 이어집니다. 수학·영어·독서·미술·음악·코딩 예시를 제공하며 자동 공개하지 않습니다. 상담 안내서는 기존 상담에 연결할 수 있고, 학원별 지도·피드백·준비 기준을 함께 관리합니다. 기준을 저장했다고 AI가 학습되거나 성과가 자동 개선되는 것은 아닙니다.

**최종 검토 개선:** 자료함에서 제목·반을 검색하고, 기존 승인본을 유지한 채 별도 새 초안으로 재사용할 수 있습니다. 가정별 안내서는 복제 시 이전 가정의 자유 입력과 상담 연결을 비웁니다. 체험한 반이 상담 신청 폼에 이어지고, 원장실 상담 목록에서 해당 상담의 안내서를 바로 준비합니다. 반 변경 중 오래된 상담 시간 응답은 무시하며 통신 실패 재시도에도 저장된 신청을 중복 생성하지 않습니다. 모바일 작성·검토 이동, 정답 확인, 입력 충돌 보존도 보완했습니다. [최종 통합 검토](FINAL_REVIEW_2026-09-25.md)에 사업 판단·수정 내용·남은 운영 범위를 정리했습니다.

안내서 링크는 1~30일 동안 열리며 원장이 공유를 중지할 수 있습니다. **링크를 가진 사람은 읽을 수 있는 방식**으로 보호자 본인 인증은 아닙니다. 교사용 메모는 공개 응답에서 제외합니다. 수강료·시간표·학원 기준 등 원본 정보가 바뀌면 공유를 잠그고 재검토를 요구합니다. 승인본은 별도 변경 불가 기록으로 남습니다. 체험 통계는 익명 세션·완료·상담 버튼 선택이며 등록 성과로 표시하지 않습니다.

공개 체험의 **선택적 Gemini 초안 생성 어댑터**를 구현했습니다. 이 프로젝트의 `.env`에 서버 전용 `ACADEMY_GEMINI_KEY`, `ACADEMY_GEMINI_MODEL`을 모두 설정하고 서버를 다시 실행하면 활성화됩니다. 실제 호출에는 비용이 발생할 수 있습니다. 개인정보 없는 공개 자료를 전달하는 동의를 받은 경우만 호출하며 초안 검토·승인은 별도입니다. 키가 없으면 직접 작성·예시를 이용합니다. 실제 모델 응답은 아직 실환경 검증하지 않았고, 기존 웹사이트 제작·업무 직원은 로컬 서식 처리입니다.

**[웹사이트 만들기](http://localhost:5173/start)**는 Beauty OS와 같은 두 가지 제작 경로를 제공합니다. **프리미엄 템플릿**은 미리보기 → 디자인·영상 선택 → 학원 정보 확인 → 적용, **맞춤형 제작**은 학원 링크·문서 자료 → 로컬 초안 → 원장 수정·확인 → 적용입니다. PC·모바일 미리보기, 영상 추천·매일 교체, 주소 복사, 제작 이력을 제공합니다. **[학원 웹사이트](http://localhost:5173/site)**와 **[원장실](http://localhost:5173/#website)**은 같은 기록을 사용하며 기존 학생·예약·게시물을 유지합니다.

기존 6종에 website108 학원 디자인 11종(조잘·셈틀·책고리·궁리·여음·모눈·필선·가로줄·요모조모·등불·틈새)을 추가했습니다. 추가 디자인은 홈·학원 소개·수강 안내·배움 이야기·상담 페이지를 제공합니다. 원본 사진·글꼴과 디자인 방향을 학원 데이터용 레이아웃으로 적용했으며, 원본 HTML의 모든 개별 섹션을 그대로 복제한 것은 아닙니다. 원본의 예시 가격·지점·일정 대신 저장된 수업과 승인한 소개·소식을 보여줍니다. 자산 출처는 `public/templates/provenance.json`, 가져오기 도구는 `scripts/import-academy-library.ps1`입니다.

맞춤 제작 링크는 공개 HTTPS HTML·텍스트를 가져옵니다. 접근이 제한되거나 JavaScript 실행이 필요한 페이지는 직접 소개를 붙여 넣어 주세요. TXT·MD·CSV는 파일당 50KB, 최대 5개, 자료 합계 12,000자까지 지원합니다. 사진·PDF 분석과 외부 AI 생성은 아직 연결하지 않았으며, 로컬 자료 정리를 AI 생성으로 표시하지 않습니다. 초안과 보류 이력은 서버에 저장되고 원장만 접근할 수 있습니다.

예약·문의 직원(`CORE-01`)과 콘텐츠 생성 직원(`CORE-08`) 두 명이 무료 제공 상품의 기본 구성입니다. 예약·문의의 내부 처리기를 직원 두 명으로 세지 않습니다. 콘텐츠 화면에서는 주제·확인된 자료 → 로컬 초안 → 수정·승인 → 선택한 웹사이트 게시까지 체험할 수 있습니다. **실제 외부 AI 생성과 agent1000 운영 계정·DB 연결은 아직 완료되지 않았습니다.** 자료 정리 기능을 모델 생성으로 표시하지 않습니다.

원본 플랫폼의 템플릿 ID·CSS·영상 자산을 재사용하고, 여섯 히어로 구성을 현재 학원 데이터에 맞게 적용했습니다. 과거 전체 HTML의 예시 합격 실적·가짜 지점·미연결 상품 판매를 복사하지 않았습니다. 원본의 모든 하위 페이지를 그대로 이식한 버전은 아닙니다. 출처 해시는 `public/designs/provenance.json`, 재현 도구는 `scripts/import-academy-designs.mjs`입니다. 미리보기는 저장값을 바꾸지 않으며 신청 버튼도 비활성화합니다.

학원 운영을 로컬에서 검증하는 서버 기반 앱입니다. 가상 학원과 예시 학생 데이터로 시작합니다. 원장·강사·학부모·학생 화면, 검수·결재, 수납 장부, 상담과 공개 페이지가 같은 SQLite 기록을 사용합니다.

## 실행

Windows에서 `START.cmd`를 더블클릭합니다. 5173~5182에서 이번 수업 스튜디오 버전의 서버 또는 빈 포트를 찾아 엽니다. 예전 버전이나 다른 앱의 프로세스를 종료하지 않습니다. `PORT`를 지정하면 해당 포트만 사용하며 충돌 시 오류를 안내합니다. `powershell -File START.ps1 -NoBrowser`는 브라우저 없이 숨김 서버만 준비합니다.

터미널에서는 Node.js **24.14.0 이상**으로 실행합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

- 원장실: http://localhost:5173
- 로컬 공개 페이지: http://localhost:5173/?portal=1
- 빌드한 화면: `npm.cmd run build` 이후 `npm.cmd start`
- 로컬 서버는 `127.0.0.1`에서만 수신합니다. 다른 기기나 인터넷에서 열리는 배포 주소가 아닙니다.
- `START.cmd` 로그: `%LOCALAPPDATA%\AcademyOS\server-<포트>.stdout.log`, `server-<포트>.stderr.log`.

## 계정과 데이터

기본값은 **로컬 체험 모드**입니다. 상단에서 원장, 강사 2명, 이서준 학부모, 이서준 학생 계정을 바꿉니다. 각 요청은 서버 세션의 역할과 담당 반·학생 관계로 검사합니다. 체험 모드 자체는 누구나 예시 원장으로 들어갈 수 있으므로 실제 개인정보를 넣지 마세요.

암호 확인을 사용하려면 기존 서버를 종료하고 다음처럼 실행합니다.

```powershell
$env:ACADEMY_DEMO = '0'
npm.cmd run dev
```

최초 실행 시 생성한 계정별 암호는 `%LOCALAPPDATA%\AcademyOS\data\local-accounts.txt`에만 저장됩니다. 이 파일을 공유하거나 Git에 넣지 마세요. 계정과 보호자 연결은 아직 예시 계정으로 고정되어 있으며, 실제 회원 초대·본인 확인·다학원 가입 기능은 없습니다. 암호 모드는 이 기능들을 대신하지 않습니다.

기본 SQLite 경로는 `%LOCALAPPDATA%\AcademyOS\data\academy.sqlite`입니다. OneDrive 폴더의 실시간 동기화와 WAL 파일이 충돌하지 않도록 소스 폴더 밖에 둡니다. 테스트 또는 별도 설치에서는 `ACADEMY_DATA_DIR` 환경 변수로 바꿀 수 있습니다. Windows 외 환경은 프로젝트 `data/`가 기본값입니다.

기존 브라우저의 `wonjangsil-v3` 기록은 삭제하거나 자동 이관하지 않습니다. 설정의 **이전 체험 기록 내보내기**로 원본을 보관할 수 있습니다. 과거 모의 출결·수납을 확인 없이 실제 장부에 합치지 않습니다.

## 확인할 수 있는 업무

1. 강사로 수업 날짜 선택 → 관찰한 학생만 출결·숙제·이해도 저장.
2. 강사가 리포트 검수 → 원장이 본문·근거·수신자를 확인하여 결재.
3. 서버 작업자가 승인 스냅샷을 로컬 학부모 화면에 반영. 수정 시 새 검수·결재가 필요합니다.
4. 원장에서 학생 등록·반 이동·퇴원, 신규 반, 요일별 시간표 변경안과 적용일, 청구·입금 기록·제한된 환불 계산.
5. 공개 페이지의 상담 신청 → 중복 시간 검사 → 원장 확정 → 학생 등록·첫 청구서 연결.
6. 방문자 문의 → 확정한 지식 또는 원장 답변 → 본인의 확인번호에서 답변 열람.
7. 예시 문항 선택 → 강사 검수·원장 승인 → 해당 학생에게 문항 공개·서버 채점.
8. 콘텐츠 작성·수정·결재 → 승인한 본문을 로컬 공개 페이지에 반영.

출결을 입력하지 않으면 미관찰로 남습니다. 과거 데이터가 없으면 통계나 상담 성과를 만들어 표시하지 않습니다. 로컬 업무 처리기는 **규칙·서식 기반 작업**이며 외부 AI 모델이 아닙니다. 업무실에서는 예약·문의 처리기를 하나의 직원으로 묶어 표시합니다.

## 백업과 복구

설정에서 받는 JSON은 업무 기록의 검토·이관용 내보내기입니다. 계정과 세션을 포함한 완전한 복구에는 SQLite 백업을 사용합니다.

```powershell
npm.cmd run backup
```

실행 중인 DB도 SQLite 백업 API로 일관되게 복사하고 `PRAGMA integrity_check` 결과를 확인합니다. 백업은 데이터 폴더의 `backups/`에 생성됩니다. 백업도 개인정보와 계정 해시가 있는 로컬 파일이므로 별도 보관 정책이 필요합니다.

원본을 덮어쓰지 않고 복구를 점검하는 방법:

1. 복구용 새 빈 디렉터리를 만들고 검증할 백업을 그곳에 `academy.sqlite`라는 이름으로 복사합니다.
2. `ACADEMY_DATA_DIR`을 해당 디렉터리, `PORT`를 빈 포트(예: 5174)로 설정해 서버를 실행합니다.
3. 학생·수납·결재 내역을 확인합니다. 백업 이후의 기록은 해당 백업에 포함되지 않습니다.
4. 실제 데이터 교체는 기존 서버를 종료한 뒤 수행합니다. 실행 중인 DB 본체만 직접 복사하거나 WAL 파일을 삭제하지 마세요.

백업을 실제로 다시 여는 회귀 테스트가 있습니다. 자동 백업 스케줄, 외부 보관, 암호화, 복구 UI는 아직 없습니다.

## 구조와 검증

- `src/app.js`: 화면 상태·탐색·사용자 요청 처리.
- `src/views.js`, `src/dialogs.js`, `src/portal.js`, `src/ui.js`: 역할별 화면·폼·공개 페이지·공통 표현.
- `src/api.js`: 세션·CSRF·API 오류 처리. `src/styles.css`: 숲색·크림·세이지 디자인과 반응형.
- `shared/core.js`: 한국 날짜·시간·금액·수업 회차·관찰 신호 계산.
- `server/index.js`: HTTP/API·세션·Origin/Host·입력 크기·요청 빈도 검사와 서버 작업자.
- `server/domain.js`: 권한, 입력 검증, 업무 규칙, 검수·결재·공개 범위.
- `server/store.js`: SQLite 트랜잭션, 변경 버전, 중복 요청 방지, 불변 원장·승인·감사 이력.
- `server/seed.js`: 명시적인 예시 계정·학원·직접 작성한 문항.
- `tests/`: 업무, 저장·복구, 암호 로그인/API, 격리된 브라우저 검증.

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run test:website
npm.cmd run format:check
npm.cmd run build
```

브라우저 검증은 Windows의 Microsoft Edge를 사용하며 별도 임시 DB를 생성합니다. 실사용 로컬 기록을 변경하지 않습니다. `PLAYWRIGHT_CHANNEL`로 설치된 다른 Chromium 채널을 지정할 수 있습니다. GitHub Actions에는 형식·업무/API·빌드 검사를 추가했습니다. 현재 로컬 검증과 원격 CI 실행은 구분합니다.

## 실제 서비스 전 남은 범위

외부 LLM, 문자·알림톡, 결제·은행 대사, agent1000 플랫폼은 연결되지 않았습니다. 실제 발송·입금 확인·AI 진단으로 표시하지 않습니다. 환불은 명시된 제한 조건의 계산과 로컬 장부 조정이며 실제 송금이 아닙니다.

SQLite 엔티티별 JSON 테이블과 학원 단위 변경 버전은 작은 로컬 앱을 위한 구조입니다. 모든 학생·청구 관계가 관계형 외래키로 정규화된 구조는 아니며, 다학원 SaaS를 위한 회원 관리·데이터 격리 운영·마이그레이션·페이지 단위 조회·대규모 부하 검증이 완료된 것은 아닙니다. 실제 운영 확장 시 이 경계를 기준으로 정규화와 모듈 분리를 진행해야 합니다.

현재 사용자·보호자 연결은 고정 예시입니다. 대량 명부 이관, 여러 반 동시 수강, 교사 계정 관리, 일반적인 결제 취소·수납 대사, 전체 교육과정 문제은행과 진단 검사는 제공하지 않습니다. 로컬 체험의 정상 동작과 실제 학원의 운영 준비 완료는 다릅니다.

이 버전은 Node 서버와 영속 DB가 필요합니다. 기존처럼 `dist/`만 Vercel 정적 사이트로 배포하면 API가 동작하지 않습니다. 실제 배포는 영속 서버/DB, HTTPS, 계정·보호자 검증, 외부 공급자 연결을 별도로 설계해야 합니다.
